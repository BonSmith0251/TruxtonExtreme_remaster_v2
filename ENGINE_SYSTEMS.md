# Engine systems and remaining recovery work

This is a compatibility reconstruction for Unity 2023.2.22f1 from a Unity 6000.3.7f1 IL2CPP player. Asset import, script attachment, executable behavior, and original-game fidelity have separate meanings. The final validation results are in RECONSTRUCTION_REPORT.md and verification.

Three source objects still have strict schema failures: PlayerSettings, the source URP global-settings object, and one built-in managed object. Their raw bytes remain available. The decoded source reference graph resolves 945,368 non-null pointers, but this is not proof that every corresponding target reference or imported field is equivalent.

Recommended recovery order: finish exact source-to-target identity mapping; recover the original startup dependency chain; rebuild addressable entry/transition behavior; then restore one original stage end to end with matched recordings. Advance rendering, sound and combat fidelity through measurements of that stage before claiming whole-game recovery.

The final standalone build also exposed an OutGame reflection warning. Five generated coroutine types have fields of UnityEngine.AsyncInstantiateOperation<T>, which is absent from the target Unity 2023 Core module. The affected original owners are ModelGamePlayBase.LoadResidentData, PipiruVillagePresenter._instantiateStage, OutGameHelper.SetupFunctions, OutGameHelper.SetupUIGuides, and ModelViewerPresenter/ModelMan.load. These workflows need an evidence-based asynchronous-instantiation port; a blanket stub or warning suppression would not restore them. An unused private UniTask particle callback had an invalid target-engine signature. A documented compatibility rename prevents its registration; public APIs and method bodies are preserved, and no source serialized attachments or consuming call sites were found. This restores no additional particle behavior.
The recovered TXE_PipelineAsset can construct its target renderers for a temporary static BG01/BG03 probe with the original camera renderer indices and zero probe errors. Only limited geometry/textures were visible at the preserved initial poses. The default project pipeline remains the supplemental Round 1 pipeline; native camera index 1 falls back when that default is used. Correct pipeline selection alone does not restore original timeline activation, custom shader behavior or complete stage presentation.

The remaining stage work is the InGame.Kernel timeline layer: EnemyEntry/EnemyWave (ground and wave spawns), TLEntry (wave sub-timelines with game-mode, weapon and zone flags), EventEntry (items and drops), BGMEntry (music sections), AreaEntry, BGSlideRange (horizontal parallax) and CameraPers. Their clip data is intact and readable, so these are the next native recovery targets for an end-to-end stage. Custom shaders are now the main visual gap in the presented stages.
